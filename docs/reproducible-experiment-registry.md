# Reproducible Experiment Registry

## API

All endpoints require the configured `X-API-Key`.

- `POST /api/v1/research/experiments` records an offline experiment manifest.
- `GET /api/v1/research/experiments?limit=50&symbol=EURUSD&timeframe=M15` lists recent runs with optional symbol/timeframe filters.
- `GET /api/v1/research/experiments/{run_id}` retrieves a stored run and fold-level results.

The POST body requires `run_id`, `dataset_sha256`, `symbol`, `timeframe`, `protocol_version`, and a JSON `manifest`. The manifest may include the experiment matrix output generated by `app/research_experiment_matrix.py`. Fold results are retained as submitted for traceability; the API does not independently recompute model metrics.

## Reproducibility and idempotency

A canonical JSON representation of the dataset digest, symbol, timeframe, protocol version, and manifest is SHA-256 fingerprinted. Repeating the same run ID with the same content is idempotent. Reusing a run ID with changed content returns HTTP 409. A matching fingerprint under a different run ID resolves to the existing record. Database uniqueness constraints protect both run IDs and fingerprints against concurrent duplicates.

## Guardrails and interpretation

- Rejects malformed dataset SHA-256 values and manifests marked actionable, automatic-winner-selected, or tuned on test metrics.
- Stores an audit event for each new registration.
- Read endpoints are authenticated and do not modify records.
- All responses mark the registry non-actionable. The registry does not promote models, issue trading signals, call a broker, or change Auto Live/execution/risk controls.
- A hash proves identity of the submitted bytes/manifest, not that data is truthful, point-in-time clean, leak-free, or independently validated. Fold metadata and model metrics remain operator-supplied research artifacts.
